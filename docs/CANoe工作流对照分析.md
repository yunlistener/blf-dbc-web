# CANoe 总线分析工作流对照分析

对照 Vector CANoe 的总线分析标准工作流,梳理 blf-dbc-web 项目的差距与补充项。
基于真实数据画像:EEA(5.1) CANFD DBC(45 报文 / 956 信号)+ T1V 日志 BLF(**23.3 万帧 / 46s / 109 个 ID / 约 5k 帧每秒**)。

## 一、CANoe 总线分析标准工作流(离线分析)

### 1. 工程准备
- 新建工程、配置通道(CAN/CAN FD/LIN)、总线波特率
- 加载 DBC 数据库(报文/信号/值表/周期定义)
- 导入日志文件(BLF/ASC),选择分析目标

### 2. 观测(看数据)
| CANoe 窗口 | 用途 |
|---|---|
| **Trace 窗口** | 报文流:时间戳/ID/名称/DLC/数据字节/方向(Rx/Tx)/通道;过滤、搜索、标记(Bookmark) |
| **Graphics 窗口** | 信号曲线:多信号叠加、缩放平移、游标测量(Δ 差值)、波形统计 |
| **Statistics 窗口** | 总线负载率、每 ID 帧计数/速率、DLC 分布、错误帧统计 |
| **Data 窗口** | 信号数值表格(选中信号的逐帧数值) |

### 3. 分析(信号级)
- 信号数值统计:min / max / mean / std、峰值、变化率
- 周期与抖动:实际发送周期 vs DBC 定义周期(cycle_time),Jitter 分析
- 值表信号:状态(choices)占比、状态切换次数
- 信号范围检查:超出 DBC 定义的 minimum/maximum 标红
- 丢帧/周期超时检测

### 4. 诊断(总线级)
- 总线负载率(Bus Load)
- 错误帧定位(时间点、ID、错误类型)
- 报文缺失/中断(该发的没发)
- 信号异常:跳变、卡死、超范围

### 5. 导出与报告
- CSV/Excel 导出(信号数据、统计结果)
- 图表截图、HTML 报告
- 多文件对比分析

## 四、建议迭代计划

**迭代 M4(P0,一次做完)**:文件切换器 → 报文搜索 → 解析缓存 → 信号统计 → Bus Load → 周期/抖动
**迭代 M5(P1)**:Trace 增强(通道/方向/过滤)→ 游标 Δ → 值表统计 → 超范围 → 区间导出
**迭代 M6(P2)**:多文件对比 → HTML 报告 → 数据表格 → 搜索帧

## 五、关键技术点备忘

- **Bus Load 公式**:Σ(帧长 bit + 帧间隔 3 bit + EOF 7 bit) / (总线速率 × 时长)。CAN FD:仲裁段(SOF+ID+DLC+数据+CRC+ACK+EOF)与数据段速率不同,需分段计算;波特率由用户输入
- **周期/抖动**:对同 ID 帧时间戳做差分 → 与 cycle_time 对比,超 ±20% 记抖动;相邻帧间隔 > 2×cycle_time 记丢帧候选
- **解析缓存**:BLF 流式解析一次,按 arbitration_id 聚成内存 dict(id → [(ts, data_bytes)...]),23 万帧约几十 MB,完全可接受;decode/frames/export 全走缓存,后续 0 扫描
- **值表统计**:DBC 信号 choices 字段;统计各状态帧数 + 时间占比(状态保持时间按相邻帧时间差)
- **超范围**:DBC 信号 minimum/maximum;BLF 解码时比对,返回越界点列表
- **文件切换**:后端 files API 已返回全部文件,前端加下拉即可;切换时重置所有状态(曲线/Trace/统计)
- **stats 小 bug**:`blf_parser.stats()` 的 by_id 条目补 `frame_id_hex` 字段
