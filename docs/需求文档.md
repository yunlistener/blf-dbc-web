## 1. 项目概述

### 1.1 目标

基于网页的 CAN/CAN FD 总线日志(BLF)分析平台:上传 BLF 日志 + DBC 数据库 → 浏览器中按 **CANoe 操作流程**(配置网络 → 添加信号 → **播放**)查看动态曲线、统计分析、导出。部署于树莓派(ARM64),局域网内浏览器访问,数据不出内网;后期扩展**实时接收报文**解析渲染。

### 1.2 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| BLF 解析 | python-can(BLFReader) | 官方生态,读 BLF v1/v2/v3;与 cantools 天然配合 |
| DBC 解析 | cantools | 事实标准,值表/多路复用支持 |
| Web 后端 | FastAPI + Uvicorn | 异步高性能、Swagger 文档、内存 <100MB |
| 前端 | 原生 JS + uPlot(本地化 vendor/) | 百万点级流畅;min/max **保形降采样**保留尖峰;无 CDN 依赖 |
| 实时通道(后期) | socketcan(CAN 接口) | 与离线 BLF 统一为帧源 |
| 数据推送 | WebSocket(后端→前端帧流) | 动态回放 + 实时接收共用 |
| 部署 | systemd 常驻 + Uvicorn 直接服务 | 免 Docker、免编译(ARM64 全 wheel) |

### 1.3 里程碑状态

| 阶段 | 内容 | 状态 |
|---|---|---|
| M1 | 后端骨架:上传、DBC 解析 API、BLF 统计/解码 API | ✅ 完成 |
| M2 | CANoe 风格界面:报文树、多示波器、Trace、统计、导出 | ✅ 完成 |
| M3 | 树莓派 systemd 部署 | 🔶 首次部署完成,RPi 宕机待重装 |

## 2. 功能需求(已实现)

### 2.1 文件管理

- 上传 `.blf` / `.dbc` 文件(multipart,拖拽/多选);文件列表、删除
- 配置持久化(`data/config.json`):默认 BLF/DBC、每通道 DBC 映射

### 2.2 DBC 解析(中文乱码已根治)

- 报文列表:ID(hex)、报文名、长度、信号列表、**发送 ECU 列表(senders)**
- 信号详情:起始位/位长/字节序/缩放/偏移/单位/**值表 choices**/min-max/**中文说明 comment**
- **编码自动检测**:UTF-8 → GBK → GB18030 strict 校验回退 + `lru_cache`(真实 EEA DBC 为 GBK)

### 2.3 BLF 解析与性能

- **帧索引缓存**(`blf_cache.py`):首次全扫建帧索引 + LRU 4 文件/200 万帧 + mtime/size 校验;decode/frames/export 统一走缓存,**27 倍提速**(0.56s→0.02s)
- 流式解析,内存预算 ~1GB;`max_points=200000` 降采样上限
- 无数据报文三层处理:decode 空返回 200+empty;前端选中容错回滚;信号树灰标+删除线

### 2.4 信号选择与示波器(核心)

**布局(CANoe 式)**:
- 左侧信号树(1/3 宽,搜索/排序)→ 已选信号列表(80~320px 可拖)→ 示波器区(上下排列、横贯全宽、固定高度、纵向滚动)
- **多示波器窗口**:默认每信号一个;`+/−` 按钮增删空示波器;**添加信号优先复用空示波器,无空才新建**
- 标题栏:示波器号 + `+ 信号` 按钮 + 信号列表(色点+名称+**✕ 删除**)

**信号添加/分配**:
- 信号树点选 → 添加/删除(复用空示波器)
- 示波器 `+ 信号` 模态:**只列已选信号列表里的信号**(免 API 复制),标注"已在示波器 N"
- **同一信号可同时在多个示波器显示**(去重:frame_id+signal+channel+plotId 四元组)
- 信号上限 **64**;20 色调色板循环

**坐标轴与时间同步**:
- **同窗共享 y 轴**:范围自动聚合窗口内全部信号值域 + 15% padding,移入移出重算
- **示波器光标同步**:鼠标在某示波器移动时,其他示波器垂直虚线跟随(时间对齐位置);竖线 draw hook 自绘贯穿全高
- **测量锚点**:点击设置/清除,红色虚线 + 顶部红三角,所有示波器窗口同步
- **同窗多信号时间对齐**:各信号时间戳浮点不重合 → 时间桶对齐(自适应桶 = 信号中位周期一半,上限 5ms),x 并集不翻倍、零填充、采样率零增加,曲线连续(CANoe 同窗行为)
- **y 范围对齐刻度 step 倍数(向下取整)**:负值信号负数刻度可见
- 每窗口底部有**时间轴刻度**(同步后上下对齐);缩放/框选/重置全窗口广播
- 恒值信号扩开一格显示

**曲线渲染**:
- 普通信号:连续折线(宽度 2)
- **值表信号(choices)**:linear 折线 + **前向填充**(状态保持到下一采样,等效阶梯)

**交互**:
- 光标 tooltip:时间 + 各信号值(名称(值)+ 单位)
- 框选放大、重置;**双点测量**(点击设黄色锚点,显示 Δt/频率)
- **抖动峰值标记**:时间轴顶部信号色小三角(配置抽屉可开关)
- 示波器高度三档把手:全页 / 2/3 / 收起

### 2.5 底部标签页

**Trace 帧浏览**:时间/ID/报文/DLC/**FD 标记**/**CH 列**/数据 hex;值搜索;**缩放区间过滤**;清除
**ID 统计**:每 ID 帧数/频率/时间范围;顶部总线负载率条(CAN/CAN FD 位时近似)
**信号统计**:点数/min/max/mean/std/最后值(带单位)/**超范围检测**(DBC min/max 标红)/值表分布/**周期抖动**(期望/实测/峰峰/丢帧/峰值时间点);tab 打开时增删信号自动刷新

### 2.6 导出

- **CSV 区间导出**:自动带当前缩放区间(start/end)

### 2.7 配置抽屉

- 默认文件、通道 DBC 映射(后端 config);**标记抖动峰值**开关(localStorage 即时生效)

### 2.8 持久化(刷新恢复)

- 已选信号(含示波器 plotId)存 localStorage,刷新自动恢复;三态:首次(自动选默认)/有记录(恢复)/已清空(保持空)
- **清空按钮**;beforeunload 兜底保存

### 2.9 版本号

## 3. 新增需求:播放模式 + 动态解析推送(★ 本文档重点新增)

### 3.1 需求背景

对齐 CANoe 操作流程:**配置完网络、添加完信号,点击"播放"按钮,曲线才会动态显示**。当前实现是"选完信号立即一次性渲染全部曲线",与 CANoe 的"回放"体验不符;同时要为**后期实时接收报文并解析渲染**保留一致的前端接口。

### 3.2 操作流程(CANoe 式)

```
① 配置网络:选 BLF + DBC、各通道 DBC 映射(配置抽屉)
② 添加信号:信号树点选 / 示波器 + 信号(现有流程)
③ ▶ 播放:曲线开始动态显示(时间推进、数据逐帧追加)
④ 播放/暂停/停止;进度条拖动定位
```

- 配置完信号后,**不播放不显示曲线**(或显示"就绪"状态)
- 点播放后,曲线随时间轴**动态增长**,像示波器实时回放
- **时间轴固定**(全量范围),曲线在固定时间轴上从左向右画出,**不扩张**
- **毫秒级渲染**(前端 rAF 驱动,非 200ms 节流),曲线平滑无跳跃

### 3.3 架构设计(前后端一致接口)

```
后端帧源抽象 FrameSource(统一帧流输出)
├─ 离线 BLF 回放器:逐帧读取(帧索引缓存加速),按回放速率推送
└─ 实时 CAN 接收器(后期):socketcan 接收,同格式输出

传输:WebSocket(后端 → 前端推送帧批次数据)
格式:批次 { timestamp, frame_id, data_bytes } 或直接解码后 { timestamp, signal: value } 序列

前端 StreamRenderer(增量渲染管线)
├─ 接收帧批次 → 追加到 uPlot 数据 → 动态滚动渲染
├─ 播放状态机:play / pause / stop
└─ 数据源无关:离线回放与实时接收调用同一渲染接口
```

**关键设计**:
1. **帧源抽象**:离线 BLF 回放器与实时 CAN 接收器实现同一 `FrameSource` 接口,输出统一格式 → 后端切换数据源不改渲染逻辑
2. **WebSocket 推送**:帧批次按回放速率(0.5x/1x/2x)推送,支持流量控制
3. **前端渲染接口统一**:`StreamRenderer` 只认"帧批次数据",不关心数据来自离线回放还是实时接收 → M4 与 M5 前端零改动
4. **播放控制**:▶ 播放 / ⏸ 暂停 / ⏹ 停止 / 进度条(拖动定位回放位置)
5. **与现有一次性渲染共存**:播放模式为新增渲染路径;静态分析(统计/导出)仍走现有 API

### 3.4 验收标准

- 配置完信号后无曲线;点播放后曲线随时间动态出现
- 播放/暂停/停止/进度拖动正常;回放速率可调
- 帧批次推送 + 增量渲染接口与实时接收模式一致(后期接入 socketcan 数据源即可复用)

## 7. 已踩坑与决策记录

### 7.1 uPlot 1.6 系列坑(源码级确认)

| 坑 | 表现 | 修复 |
|---|---|---|
| `range` 回调只在无数据聚合时调用 | y 范围错误(0~247 显示 189~191) | setData 后显式算 y 范围并 setScale |
| series 创建时固定,setData 不能加列 | 同窗多信号新曲线消失 | 信号数变化时销毁重建 uPlot |
| 后创建窗口 x scale 不自动计算 | x 范围 undefined,时间轴不画 | 显式 setScale x |
| 未指定 scale 的轴按 side 猜测分配 | x 轴被猜成 y scale | 所有轴显式 `scale:"x"/"y"` |
| side 枚举 0=上/1=右/2=下/3=左(反习惯) | y 轴画顶部、时间轴竖排 | 按真实枚举配置 |
| 刻度从 min 向上取整到 step 倍数 | 负值信号无负刻度 | y 范围对齐 step 倍数向下取整 |
| `uPlot.paths.stepped` 依赖 scale.dir/ori | 值表信号空路径不渲染 | linear 折线 + 前向填充 |
| 多余预创建 y scale 自动生成空右轴 | 窗口右侧空刻度 | 多余轴显式 `show:false` |

### 7.2 后端与工程

- cantools 对 GBK 字节静默乱码 → 主动编码检测(strict)
- BLF 双通道 37 个重叠 ID,必须按通道配置 DBC 解码
- 值表信号 decode 返回 dict(`{name,value}`),per 构建提取 `.value`
- Mac 双 Python:Xcode 3.9 跑服务(pip 包装在这);FastAPI 用 `Optional` 禁止 `X|None`
- rsync 排除 `.venv` 且 exclude 不带引号;前端改动必须 bump `?v=N`
- 凭据安全:GitHub PAT 存 `~/.git-credentials`;飞书/RPi 凭据不入文档
