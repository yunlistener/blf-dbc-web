## 1. M4 播放模式开发步骤

> 目标:配置网络 + 添加信号后,点"播放"→ 曲线动态显示(后端 FrameSource 逐帧推送,前端 StreamRenderer 增量渲染);与后期实时接收共用同一管线。
> 详细设计见《系统设计》§4-§7(帧批次协议 / PlaybackEngine / StreamRenderer)

### M4-1 后端:FrameSource 抽象 + BlfReplaySource
- [ ] 定义 FrameSource 接口:`open / read_batch(batch_size) / seek(t) / close`,输出统一帧流
- [ ] BlfReplaySource:基于现有 blf_cache(索引)+ blf_parser 实现时间顺序批量读帧 + 二分定位 seek
- [ ] 复用 decoder 抽"帧批次解码"(帧 → 已选信号值),与 REST decode 共享内核
- **验收**:Python 脚本直接调用,能按时间顺序批量取帧、seek 到任意时间点;全量 23 万帧预读 < 3s

### M4-2 后端:PlaybackEngine(回放引擎)
- [ ] 播放状态机:`idle / playing / paused / stopped`
- [ ] 速率控制:`rate`(0.5x/1x/2x/5x),按回放时钟推进(真实时间映射)
- [ ] 信号订阅过滤:只解码并推送已选信号
- [ ] `seek(t)` 重置位置
- **验收**:按 1x 回放 46s 数据,推送节奏 ≈ 真实时间;2x 时解码吞吐余量充足(见技术评估)

### M4-3 后端:WebSocket 网关
- [ ] `WS /ws/replay` 端点:连接 → 建会话(源+引擎+订阅)→ 收控制指令(`play/pause/stop/seek/rate`)→ 推帧批次(`{seq, t0, rate, t[], signals{}}`)
- [ ] 会话管理(连接断开清理);与 REST API 共存(FastAPI 原生 WS)
- **验收**:wscat/脚本连接,发 play → 收到连续帧批次,seq 递增;断开重连可续推

### M4-4 前端:WS 客户端 + 播放状态机
- [ ] WS 封装(重连、心跳、seq 对账)
- [ ] 播放状态机(play/pause/stop/seek/rate 指令发送;按钮态同步)
- **验收**:播放按钮切换状态,控制指令正确发出

### M4-5 前端:StreamRenderer(增量渲染)
- [ ] 增量 append:维护累积 `t[]/values[]` 数组,帧批次到达 → `uPlot.setData`(新数据合并)
- [ ] 与静态模式并存:播放模式用增量,静态(信号树直选)用现有全量 draw
- [ ] 动态时间轴滚动(窗口跟随当前时间)
- **验收**:播放时曲线随时间增长;暂停即停;seek 后重绘

### M4-6 前端:播放 UI
- [ ] 示波器区顶部播放控制条:`▶ ⏸ ⏹ | 进度条 | 速率(0.5x/1x/2x/5x)`
- [ ] 播放进度显示(当前时间/总时长)
- **验收**:CANoe 式操作:配置 → 选信号 → 点播放 → 曲线动态出现

### M4-7 集成验证 + 文档更新
- [ ] 全流程验证(真实 T1V 数据):播放/暂停/停止/拖动/变速
- [ ] 同步更新:需求文档(§3 播放需求标注实现状态)、系统设计(§7 协议标注落地)、本计划(勾选)
- **验收**:三文档与代码一致;功能无回归(静态分析照常)
