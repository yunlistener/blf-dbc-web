## 1. M4 播放模式开发步骤

> 目标:配置网络 + 添加信号后,点"播放"→ 曲线动态显示(后端 FrameSource 逐帧推送,前端 StreamRenderer 增量渲染);与后期实时接收共用同一管线。
> 详细设计见《系统设计》§4-§7(帧批次协议 / PlaybackEngine / StreamRenderer)

### M4-1 后端:FrameSource 抽象 + BlfReplaySource ✅
- [x] FrameSource 接口:`seek(t) / next_batch(max_frames, end_t) / close`,输出统一 `Frame{ts(相对),channel,frame_id,data,is_fd,dlc}`
- [x] BlfReplaySource:基于 blf_cache 索引,多报文最小堆 k-way merge 流式输出,每报文时间数组二分定位 seek;输出相对时间(ts - t0)
- **实测**:初始化 0.45s;23 万帧全量遍历 0.24s 时间有序;seek(20s) 精确;batch(1000)=0.198s 数据

### M4-2 后端:PlaybackEngine(回放引擎) ✅
- [x] 按通道 DBC 映射(`dbs: {channel: db}`)+ 订阅 `SignalSub(frame_id,channel,signal,dbc)`
- [x] `advance_to(play_time)`:源推进到播放时间 → 订阅帧解码 → 返回帧批次协议数据
- **实测**:全量 46s(3 信号含值表)解码 0.244s(27 批次);窗口 1s = 100 点/信号(100Hz)✓

### M4-3 后端:WebSocket 网关 ✅
- [x] `WS /ws/replay`:config(blf + signals[带dbc])→ 建会话;`play/pause/stop/seek/rate` 控制;批次 + 进度 + 状态推送;播放泵按墙钟×速率驱动(20ms tick)
- [x] 多 DBC 按通道加载;连接断开清理泵任务
- **实测**:config→state(dur 46.1);2x 播放 batch 连续推送(t1 递增);seek(30)/pause 正常
- **修复**:wall_start 未初始化 → play 时巨大播放时间(已修);堆时间戳绝对 vs 相对错位(已修)

### M4-4 前端:WS 客户端 + 播放状态机 ✅
- [x] WS 封装(自动连接);播放状态机(play/pause/stop/seek/rate 指令 + 按钮态同步)
- [x] 播放中信号变更(addSignal/toggleSignal/removeSignal/clearSignals)→ 自动暂停

### M4-5 前端:StreamRenderer(增量渲染) ✅
- [x] 累积 `playState.data[key].{times,values}`;批次到达 → 追加 → **200ms 节流** `applyPlayData()`(累积数据 → state.signals.data → draw/setData,曲线随时间增长)
- [x] 与静态模式并存(播放清空重绘,结束后保留全量)

### M4-6 前端:播放 UI ✅
- [x] 示波器区顶部播放控制条:`▶ ⏹ | 进度条 | 时间 0.0s/46.1s | 速率 0.5x/1x/2x/5x`(有信号时显示)
- [x] 进度条拖动 → seek;播放中变速

### M4-7 集成验证 + 文档更新 ✅
